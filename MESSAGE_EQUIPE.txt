Petit point sur la partie interface web frontend.

1. Interface prête dans hackathon_mobility_frontend
L'interface web complète tourne de bout en bout en mode dev sur localhost:3000. Repository organisé : composants dans components/, pages dans app/, services dans lib/, types dans types/.

2. Ce que ça fournit
• Dashboard : 4 KPIs clés (population couverte, nb stations, taux couverture, options/habitant) + graphiques répartition population (5 tranches) + camembert stations par type. Connexion API /statistics/summary et /statistics/population.
• Carte Interactive : heat map de couverture (/mobility/heatmap), marqueurs stations existantes par type (/stations), support natif GeoJSON via Leaflet, filtres région + types transport, popup détaillée au clic.
• Recommandations : formulaire configuration (région, budget, types, contraintes), calcul via /recommendations, liste triée par score d'impact avec détails (emplacement, coût, population desservie, amélioration couverture), résumé global budget/population.

3. Résultats clés
• Design professionnel : sidebar noir fixe, interface moderne, couleurs cohérentes par type (bus bleu, métro rouge, tram vert, vélo orange, autopartage violet, trottinette rose).
• Compatibilité GeoJSON native : Leaflet supporte GeoJSON RFC 7946, composant GeoJSONLayer.tsx créé, coordonnées [longitude, latitude].
• Validation contrat API v1.1 : document API_CONTRACT_VALIDATION.md avec spécification exacte des 6 endpoints MVP, points critiques (coordonnées GeoJSON, scores 0-1, types standardisés), tests curl.
• Architecture complète : 25+ composants TypeScript organisés (ui, dashboard, map, recommendations, filters), 3 hooks custom, service API axios complet, types stricts, documentation 5 fichiers MD.

Toutes les tables sont prêtes : Pages dans app/ (layout, dashboard, carte, recommandations), Composants dans components/ organisés par domaine, Services dans lib/ (api.ts, constants, utils), Types dans types/api.ts. Correspondance : zones = carreaux affichés sur carte + heat map, stations = marqueurs + liste filtrable, recommendations = liste triée + formulaire, summary = KPIs dashboard, population = graphique. Code région/ville présent dans filtres et appels API. Le détail des formats attendus est dans API_CONTRACT_VALIDATION.md.
